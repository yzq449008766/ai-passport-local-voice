## 数据流一句话

按住 OK → 每 64ms 采 2KB PCM 立即 chunked 上传（录音零内存）→ 松手 → 网关收完 → ASR 识别 → （天气问题则先查天气）→ Qwen3-VL 俏皮回答 → TTS 合成 wav → 设备边收边播，屏幕同步显示识别文本与回复 → 播完回到待机。

## 内存账（ESP32-C3 无 PSRAM，实测空闲堆 175KB / 最大连续块 114KB）

| 阶段 | 占用 |
|---|---|
| 录音 | 2KB 栈缓冲（零堆） |
| 播放 | 块队列 ≈16KB + 小块 malloc |
| HTTP/TLS | esp_http_client 2KB rx + 协议栈 |
| 整包兼容（PC 冒烟） | 录音 ≤80KB / 回复 ≤110KB |

## 为什么能"对讲机"

- **录音不限时长**：官方操作本来就是"按住说话松开即发"；低资源 ESP32 语音链路的社区共识是采集侧小缓冲 + 流式上传（声网等），我们落地为 chunked 边录边传。
- **播放不缓存**：响应音频边下边播，回复多长都不吃内存。
