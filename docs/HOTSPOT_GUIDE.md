# 工作场合联网手册（iPhone 热点承载）· P1

> 场景：工作场合没有 WiFi。目标是让工牌像 Apple Watch 一样，"手机在旁边，网络由手机承担"。
> 本文件给出近、中、远三档方案 + 固件/网关改动清单（结论来源：`AI工牌全面升级决策文档.md` §11）。

## 方案一：iPhone 个人热点（近期主路径）

### iPhone 侧（一次性设置）
1. 设置 → 个人热点 → 打开
2. **"最大兼容性"开关打开**（关键：锁 2.4GHz，ESP32-C3 只支持 2.4GHz；不开的话设备连不上/频繁掉线）
3. 记住热点名与密码（可改成简短易记的，如 `yugongpai`）

### 工牌侧（固件配置，编译前改）
`firmware/kconfig.projbuild` 里三处：
- `YOUR_WIFI_SSID` → 填 iPhone 热点名
- `YOUR_WIFI_PASSWORD` → 填热点密码
- `AIPASSPORT_GATEWAY_HOST` → 远程网关地址（P1 部署 VPS 后为域名/IP，当前开发期仍为 PC 局域网 IP）

### 掉线保活（P1 固件待做项）
iPhone 热点官方策略：**空闲约 90 秒无流量即断开**。
对策：工牌每 **≤60s** 发一次轻量心跳（HTTP GET 到网关 `/api/ping` 或复用连接保活），
即可让热点一直认为"有流量"。心跳对端网关需加 `/api/ping`（或对 `/api/health` 的短请求即可）。

> 注意：iOS 版本对热点自动关闭策略有差异，实机验证为主；长期更稳的路径是 P2 的 BLE 直连。

## 方案二：BLE 直连（P2 目标路径）

- 纯 BLE GATT，**免 MFi 认证**（Apple 官方确认对 BLE 无 MFi 要求）
- 设计原则（来自固件评估结论）：
  - **BLE 只传文本 + 控制**，ASR 放手机端（32KB/s PCM 与 BLE 实际吞吐 25-40KB/s 贴临界，传音频不稳）
  - 手机端跑 sherpa-onnx 端侧 ASR（官方支持 iOS）
  - 工牌屏幕显示 ASR 文本 + 播报回复，语音链路变短、更省电
- 固件侧：当前 BLE 栈（NimBLE）未编入构建，P2 需要接 GATT 服务 + 文本通道
